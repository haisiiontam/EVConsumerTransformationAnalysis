# 任务二总结：家庭充电条件预测（Home Charging Availability Prediction）

> 文档位置：`docs/TASK2_SUMMARY.md`  
> 对应代码：`src/tasks/task2.py`（弱信号协议 + 配置 M 多数类基线）

## 1. 任务描述

任务二要求根据消费者特征预测其是否具备家庭充电条件。

目标变量：

```
home_charging_available
```

其中：

| 标签 | 含义               |
| ---- | ------------------ |
| 0    | 不具备家庭充电条件 |
| 1    | 具备家庭充电条件   |

该任务属于典型的二分类预测问题。

---

# 2. 初始建模方案

## 2.1 基础模型

初始阶段采用：

- CatBoostClassifier
- 分层训练验证划分
- 默认分类阈值 0.5

流程：

```
dataSetB.csv
        |
        ↓
数据预处理
        |
        ↓
训练集 / 验证集划分
        |
        ↓
CatBoost训练
        |
        ↓
输出 P(home_charging_available=1)
        |
        ↓
阈值0.5转换为0/1
        |
        ↓
计算Accuracy
```

---

## 2.2 初始特征

根据赛题建议，首先使用：

- city_type
- nearest_charging_station_km
- education_level
- annual_income
- vehicle_age_years

这些变量主要用于描述：

- 居住环境；
- 基础设施距离；
- 社会经济条件；
- 车辆使用状态。

---

# 3. 初始结果分析

初始模型结果：

| 指标     |   数值 |
| -------- | -----: |
| Accuracy | 0.6495 |

进一步分析混淆矩阵：

|       | 预测0 | 预测1 |
| ----- | ----: | ----: |
| 真实0 |     2 |  3500 |
| 真实1 |     5 |  6493 |

可以发现：

模型几乎将所有样本预测为类别1。

验证集预测情况：

```
预测为0：7个
预测为1：9993个
```

---

# 4. 多数类基准分析

进一步检查标签分布：

| 类别 |  比例 |
| ---- | ----: |
| 0    | 约35% |
| 1    | 约65% |

因此，如果不建立任何模型，仅预测多数类别：

```
所有样本预测为1
```

即可获得：

```
Accuracy ≈ 0.6498
```

而初始CatBoost：

```
Accuracy = 0.6495
```

说明：

> 初始模型没有超过最简单多数类预测策略。

---

# 5. 可预测性验证

为了判断问题是否来自模型能力不足，进行了进一步实验。

验证方向：

1. 单变量分析；
2. 全字段特征分析；
3. 扩展字段分析；
4. 多模型比较。

---

# 5.1 单特征可分性分析

对所有候选变量计算：

- 单变量AUC；
- 互信息；
- 类别目标比例差异。

结果：

```
单变量AUC整体接近0.50
互信息接近0
```

说明：

单个特征无法有效区分：

```
home_charging_available = 0
```

和：

```
home_charging_available = 1
```

---

# 5.2 全安全特征模型验证

进一步扩展至18个安全字段。

实验结果：

| 模型                | 结果           |
| ------------------- | -------------- |
| CatBoost + 安全特征 | OOF AUC≈0.504  |
| Accuracy            | 接近多数类基准 |

说明：

增加特征数量并没有提高模型区分能力。

---

# 5.3 能耗和充电费用字段验证

进一步测试：

- monthly_energy_consumption_kwh
- monthly_charging_cost

等可能相关字段。

结果：

```
OOF AUC仍约等于0.50
```

说明：

这些变量也没有提供有效预测信息。

---

# 5.4 标签泄露实验

尝试加入：

```
ev_adoption_likelihood
```

发现：

```
OOF AUC≈0.61
```

说明该变量与家庭充电条件存在一定关联。

但是：

该变量属于任务一预测目标，不能作为任务二输入。

原因：

这会产生数据泄露：

```
任务二模型
        |
        ↓
使用任务一标签
        |
        ↓
人为获得额外信息
```

因此正式模型中禁止使用。

---

# 6. 最终分析结论

通过多轮实验，可以确定：

## 6.1 模型问题不是主要原因

测试过：

- CatBoost；
- 多特征输入；
- 扩展字段；
- 不同特征组合。

结果均无法明显超过多数类基准。

因此：

> 当前任务二性能瓶颈主要来自数据特征信息不足，而非模型选择不足。

---

## 6.2 数据弱信号现象

实验表明：

现有输入变量：

```
城市类型
收入
教育程度
车辆年龄
充电站距离
能耗相关变量
```

与目标：

```
home_charging_available
```

之间不存在明显统计关系。

可能原因：

家庭充电条件实际主要受以下因素影响：

- 是否拥有私人停车位；
- 房屋类型；
- 是否拥有车库；
- 物业安装限制；
- 小区充电设施条件；
- 电力容量。

但当前数据集中缺少这些关键变量。

---

# 7. 最终任务二策略

由于复杂模型无法稳定超过多数类基准，因此采用：

## Majority Class Baseline

预测规则：

```
如果类别1比例 > 类别0比例：

所有样本预测为1
```

即：

```
home_charging_available = 1
```

---

# 8. 最终模型选择理由

选择多数类模型，而不是复杂机器学习模型，原因：

| 方案           | 问题                           |
| -------------- | ------------------------------ |
| 继续调CatBoost | 无法增加有效信息               |
| 模型融合       | 多个弱模型无法创造新信息       |
| 阈值优化       | 无法解决概率排序接近随机的问题 |
| 深度学习       | 数据不足以支持复杂模型         |
| 多数类预测     | 稳定达到当前数据上限           |

因此：

> 在弱信号环境下，选择简单、稳定、可解释的方法更加合理。

---

# 9. 建模启示

任务二实验说明：

机器学习性能上限由：

```
数据质量 × 特征信息量 × 模型能力
```

共同决定。

当：

```
特征信息量≈0
```

时：

提升模型复杂度无法有效提高预测性能。

因此在实际建模过程中，应优先进行：

```
数据分析
        ↓
特征有效性验证
        ↓
模型选择
```

而不是直接进行复杂模型调优。

---

# 10. 后续优化方向

任务二后续若需要提升，需要引入新的有效信息：

例如：

- 房屋类型；
- 是否拥有私人停车位；
- 是否租赁住房；
- 物业安装限制；
- 家庭电力条件。

这些变量相比当前代理变量，更接近家庭充电条件形成机制。

但在当前数据条件下，继续增加模型复杂度预计收益有限。

---

# 11. 最终结论

任务二最终结论：

> 经过单特征分析、多变量模型实验、扩展字段测试以及泄露风险验证，发现当前数据集中可用于预测家庭充电条件的信息较弱。复杂机器学习模型无法稳定超过多数类基准，因此采用多数类预测策略作为任务二最终方案，并将主要优化资源投入到具有更强可预测性的任务一和任务三。
